- 환경: 로컬 개발 서버, 운영형 데모 데이터
- 방법: 독립 검증 에이전트 코드 감사 + 브라우저 실제 업무 시나리오 실행

## 결론

기능 부족보다 초기 화면에 너무 많은 선택지를 노출하고, 접수 후 담당 배정과 업체 정보를 다시 입력하게 만드는 절차가 가장 큰 사용성 위험이다. 핵심 업무는 정상 작동하지만 빠른 전화 접수와 모바일 현장 처리에는 단계 축소가 필요하다.

## 실제 계측

| 시나리오 | 수정 전 관찰 | 목표 |
|---|---:|---:|
| 민원 최소 접수 | 필수 6개 조작, 약 20개 라벨 동시 노출 | 필수 흐름만 먼저 노출, 상세정보 접기 |
| 민원 접수 후 현장 확인 | 접수 → 상세 → 배정 → 담당자 선택 → 배정 → 현장 확인 | `내가 처리` 1회 후 현장 확인 |
| 유지보수 접수 | 12개 입력 항목 동시 노출 | 필수 항목 + 빠른 유형, 나머지는 접기 |
| 안전점검 | 정상 항목도 개별 판정, 12회 이상 | 전체 합격 후 예외 항목만 변경 |

실제 검증 민원 `CM-20260802-180`을 접수해 상세 화면과 후속 배정 흐름까지 확인했다.

## 우선순위

### P1

1. 민원 접수 기본 화면을 빠른접수 형태로 단순화하고 추가정보를 접는다.
2. 미배정 민원에 `내가 처리`를 제공해 배정 모달을 생략한다.
3. 개인정보 동의 체크박스에 접근 가능한 이름과 연결된 라벨을 제공한다.
4. 유지보수 접수에 빠른 고장 유형을 제공하고 담당·기한·업체를 선택 영역으로 접는다.
5. 안전점검에 `전체 합격`을 제공하고 이상 항목만 수정하게 한다.

### P2

- 민원 목록의 상세 필터를 접고 긴급·기한초과·미배정·내 업무를 우선 제공한다.
- 유지보수 일괄 배정과 일괄 기한 변경을 제공한다.
- 업체 연락망을 공통 선택기로 통합하고 최근 업체를 자동완성한다.
- 문서번호 후보를 자동 추천하고 한 번에 연결한다.
- 목록 상세 진입 버튼의 접근 가능한 이름과 남은 영문 업무 코드를 정리한다.

## 합격 기준

- 민원 기본 접수에서 선택적으로 사용하는 항목은 `추가정보` 안에 있다.
- 미배정 민원은 한 번의 `내가 처리`로 담당 배정된다.
- 유지보수 접수는 주차장·빠른 유형·제목만으로 접수 가능하다.
- 안전점검 정상 결과는 한 번에 채우고 불합격 항목만 수정할 수 있다.
- 데스크톱과 390px 모바일에서 저장 버튼과 주요 행동이 가려지지 않는다.
