# 시설관리·민원관리 통합 연계성 감사

- 관찰 일시: 2026-08-02 (Asia/Seoul)
- 환경: 로컬 개발 서버와 데모 데이터
- 사용자 관점: 제주시청 차량관리과 운영팀·시설팀 주무관
- 검증 경로: 민원 접수 → 시설작업 자동 생성 → 담당업무 → 현장 증빙 → 회신·완결 → 공식문서 → 통계·보고서

## 총평

민원과 시설작업의 자동 생성 자체는 작동하지만, 권한·상태 정의·역방향 이동이 모듈마다 달라 실운영에서 업무 누락과 권한 오용이 발생할 수 있다. P0 보안 문제를 먼저 막고, 주무관이 원 민원과 시설작업을 양방향으로 오갈 수 있도록 연결하며, 업무함과 보고서가 같은 상태 정의를 사용하도록 통합한다.

## 우선순위

### P0: 즉시 수정

1. 민원 수정·배정·회신·완결 액션을 `admin`, `manager`, `editor`에게만 허용하고 DB RLS에서도 동일하게 강제한다.
2. 현장 증빙은 업로더, 작업 담당자, 관리자·팀장만 조회하도록 저장소와 첨부 메타데이터 정책을 제한한다.

### P1: 이번 수직 업무 흐름에서 수정

1. 민원 상세에 연계 시설작업과 상태·기한을 표시하고 바로 이동한다.
2. 시설작업 상세에 원 민원 이동 버튼을 제공한다.
3. 시설관리팀과 다른 팀의 사용자는 `내가 처리`를 사용할 수 없게 한다.
4. 민원·유지보수의 열린 상태를 공통 정의로 통합하고 `responded`, `completed`를 업무함에서 누락하지 않는다.
5. 최신 연계 스키마가 없을 때 무연계 작업을 조용히 생성하지 않고 명시적으로 실패시킨다.
6. 저장된 민원의 최종 기한을 자동 시설작업에 전달한다.

### P1/P2: 후속 백로그

- 민원 생성과 시설작업 생성을 하나의 DB RPC로 원자화한다.
- 시설작업 완료·검증 결과를 민원 다음 처리와 알림에 반영한다.
- 보고서 500건 제한을 페이지 조회로 교체하고 부분 조회 오류를 보고서에 표시한다.
- 공식문서 연결의 이중 저장 구조를 단일 원장으로 통합한다.
- 모바일 오프라인 초안에 사진과 영속 재시도 ID를 포함한다.
- 안전점검 불합격 작업 생성과 증빙 검증을 DB 명령으로 원자화한다.

## 측정 계약

- 대상: 시설 유형 민원 중 자동 시설작업이 생성되는 건
- 성공 이벤트: 접수 후 원 민원↔시설작업 왕복 이동, 담당 배정, 현장 증빙, 작업 검증, 민원 완결
- 목표: 재검색 0회, 중복 입력 0회, 무권한 처리 0건, 열린 업무 누락 0건
- 데이터 소스: `complaints`, `maintenance_logs`, `attachments`, `activity_logs`
- 주의: 데모 데이터는 기능 검증 근거이며 운영 성과 기준선으로 사용하지 않는다.

## 이번 수정 결과

- 애플리케이션 권한: 조회 전용 계정의 민원 수정·처리·현장등록을 차단했다.
- DB 권한: 민원 UPDATE·코멘트와 현장 증빙 접근을 제한하는 마이그레이션을 작성했다.
- 업무 연결: 민원 상세과 시설작업 상세에서 서로 바로 이동할 수 있다.
- 기존 데이터 복구: 연계 컬럼 없이 생성된 기존 작업도 설명의 민원번호로 원 민원을 찾는다.
- 상태 통합: 업무함과 보고서가 동일한 열린 민원·유지보수 상태를 사용한다.
- 실패 처리: 최신 스키마가 없을 때 무연계 시설작업을 조용히 생성하지 않는다.
- 상태 동기화: 연계 시설작업의 배정·착수·완료·검증 이력을 원 민원에 자동 반영하고, 검증 사진을 민원의 현장확인 근거로 승계한다.

## 원격 적용 및 종단 검증

- 원격 Supabase에 `20260802090000`, `20260802110000`, `20260802233000` 마이그레이션을 순서대로 적용했다.
- 실제 민원 `CM-20260802-570`을 접수해 시설작업 `CW-CM-M20260802570`이 원본 ID와 세부유형 키로 연결되는 것을 확인했다.
- 모바일 폭에서 담당자 배정 → 작업 시작 → 완료 PNG 업로드 → 관리자 검증을 실행했다.

- `20260802235500` 상태 동기화 마이그레이션을 적용하고 트랜잭션 검증에서 민원 상태·담당자·타임라인·사진 근거 자동 동기화가 통과했다.

## 역할·팀 권한 검증

`20260803002000_workflow_role_scope_hardening.sql`을 원격 Supabase에 적용하고, 동일 데이터와 JWT 조건을 트랜잭션 격리해 검증했다.

| 역할 조건 | 검증 범위 | 결과 |
|---|---|---|
| `viewer` | 민원 수정, 코멘트·첨부 등록, 시설작업 RPC, 현장 증빙 업로드 | 모두 차단 PASS |
| 타 팀 `editor` | 시설팀 민원 수정, 코멘트·첨부 등록, 증빙 조회·업로드 | 모두 차단 PASS |
| 담당 시설팀 `editor` | 담당 민원 수정·코멘트, 증빙 조회·업로드, 시설작업 착수 | 모두 허용 PASS |

시험은 각 역할별 `BEGIN ... ROLLBACK`으로 실행했다. 종료 후 `auto0104`는 `admin/admin`, 민원은 `in_progress`, 시설작업은 `verified`, 첨부 업로더는 원래 사용자로 복구됐고 임시 첨부·저장소 객체는 0건이었다. 따라서 앞서 남아 있던 역할별 부정 권한 시나리오를 완료했으며, 이번 감사 범위의 P0 잔여 항목은 없다.
