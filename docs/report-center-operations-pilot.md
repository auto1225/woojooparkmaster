# 중앙 보고서센터 운영관리 시범 계획

## 결정

- 보고서 생성, 파일 저장, 이력, 문서대장 연결은 `보고서/통계`가 단일 진입점으로 책임진다.
- 각 업무 메뉴에는 현재 업무 조건을 전달하는 바로가기만 둔다.
- 첫 표준은 `RPT-OPS-STATUS` 운영관리 현황 보고서다. 기존 `RPT-MONTHLY` 종합 월보와 분리한다.
- 수치와 표는 규칙 기반으로 생성한다. AI는 출처와 사람 검토가 있는 선택적 총평에만 사용한다.

## 주무관 흐름

1. 보고서센터에서 운영관리 보고서를 선택한다.
2. 기간, 문서번호, 공개구분, 주차장 형태와 용지 방향을 정한다.
3. 간부 보고, 실무 종합, 감사 대응 프리셋 또는 업무별 항목과 열을 선택한다.
4. 원천자료 건수와 민감정보 포함 여부를 확인한다.
5. PDF와 HWPX를 한 번에 생성한다.
6. 컴퓨터에 저장하거나 인쇄하고, 문서대장과 연결하거나 이력에서 조건을 복사한다.

## 시범 수용기준

- 기존 `/ops/report`를 포함한 모든 운영 보고서 진입점이 중앙 생성기로 연결된다.
- 조건 복사 시 기간, 업무, 열, 주차장 형태, 정렬, 방향, 공개구분이 복원된다.
- 선택한 열은 독립 열로 PDF와 HWPX에 출력된다.
- 원천자료 일부 조회 실패 시 생성을 차단하고 입력값을 보존한다.
- 모바일 390px에서 가로 스크롤 없이 작성할 수 있고 주요 체크 행은 44px 이상이다.
- 완료 후 PDF 보기, PDF/HWPX 위치 선택 저장, 이력, 문서대장 연결이 가능하다.

## 측정 목표

- 보고서센터 진입부터 파일 생성까지 중앙값 5분 이내
- 업무자료 재입력 0회
- 첫 생성 성공률 95% 이상
- 생성 파일 재열기 성공률 99% 이상
- 문서번호 연결률 90% 이상

## 다음 단계

- 시설관리와 민원관리 작성기를 동일한 카탈로그 계약으로 추가한다.
- 500건 이상 이력의 서버 검색과 페이지네이션을 도입한다.
- 생성 시도별 버전 원장과 파일 해시를 저장해 감사 추적성을 강화한다.
- 팀 단위 조회 범위와 생성 권한을 RLS에 명시한다.
- 원천 데이터 전체 대신 레코드 ID, 버전, 건수, 조회시각 중심의 출처 목록을 보관한다.
