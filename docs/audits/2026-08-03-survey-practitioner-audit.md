## 진단

기존 조사 화면은 단계별 입력은 가능했지만 저장과 다음 이동이 분리됐고, 진행 중 조사 중복 생성, 빈 조사 제출·승인, 승인 후 하위자료 수정, 비공개 사진의 공개 URL 사용, 오프라인 덮어쓰기 위험이 있었다. 또한 주차빌딩·노상·노외가 같은 조사표와 사진 분류를 사용해 현장 증빙을 구체적으로 남길 수 없었다.

## 실제 수행 결과

1. 주차빌딩 기본·운영·인프라·이용·센서계획을 단계별로 입력했다.
2. 공식 문서번호 `제주시청-차량관리과운영팀-2026-0803-현장연계01`을 연결했다.
3. 전경 PNG와 반려 보완용 램프 PNG를 실제 비공개 저장소에 업로드하고 서명 URL로 재표시했다.
4. 제출, 검토중 전환, 반려 사유 입력, 사진 보완, 재제출, 승인 및 주차장 기본정보 반영을 실행했다.
5. 승인 후 모든 조사 입력 필드가 비활성화되고 저장 버튼이 제거됨을 확인했다.
6. DB 검증 결과 상태 이벤트 6건, 승인 스냅샷 1건, 제출 검증 오류 0건, 중복 활성 주차장 0건이었다.

## 반영 사항

- `저장 후 다음`으로 단계별 클릭을 줄이고 현재 단계를 URL에 보존했다.
- 조사 작성 화면에서 공식 문서를 바로 연결하고 최종 체크리스트에 포함했다.
- 주차장 유형별 조사 항목과 사진 분류를 추가했다.
  - 주차빌딩: 층수, 소방, 환기, 승강기, 램프, 높이제한 및 관련 사진
  - 노상: 도로 구간, 측면, 통행방향, 면 번호, 표지·노면표시 및 관련 사진
  - 노외: 부지면적, 배수, 보행동선 및 관련 사진
- 비공개 사진은 10분 서명 URL로 읽고, UUID 경로·중복 업로드 금지·메타데이터 실패 시 파일 정리를 적용했다.
- DB에서 한 주차장당 활성 조사 하나만 허용하고 기존 중복 데모 조사를 사유와 함께 무효화했다.
- 제출·승인 시 기본·운영·인프라·이용·유형별 항목·사진·공식 문서 연결을 서버가 재검증한다.
- 제출 이후 하위 조사자료 변경과 승인 자료 물리 삭제를 차단하고 상태 이력 및 승인 스냅샷을 남긴다.
- 오프라인 동기화는 제출·승인 상태를 덮어쓰지 않으며 부모 조사 수정시각 충돌을 감지한다.
- 목록의 검색·필터·정렬을 URL에 보존하고 오류·빈 결과·키보드 행 이동을 보완했다.
- 인쇄 사진 분류와 입력 분류를 통일하고 비공개 사진 서명 URL, 유료·무료 제목, 주차장 유형별 문구를 적용했다.

## 지표

- 작성 단계 동작: 단계당 `저장 + 다음` 2회에서 `저장 후 다음` 1회로 감소
- 제출 누락 서버 검증: 기존 없음 → 한글 누락 목록 반환
- 활성 조사 중복: 1개 주차장에서 2건 → 0건
- 승인 증빙: 상태값만 존재 → 상태 이벤트 6건 및 승인 스냅샷 1건
- 현장 사진: 동적 파일창만 존재 → 지속 input, 모바일 후면 카메라, 서명 URL 재조회
