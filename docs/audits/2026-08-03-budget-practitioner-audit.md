# 예산관리 주무관 실사용 감사

- 관찰 일시: 2026-08-03 KST
- 환경: 로컬 Vite UI + 원격 Supabase 개발 데이터
- 대상: `/budget`, `/budget/plans`, `/budget/executions`, `/budget/transfers`, `/budget/analysis`, `/approvals`
- 사용자: 제주시청 차량관리과 운영팀 주무관, 예산 담당자, 결재권자

## 진단

기존 화면은 편성·집행·전용을 등록할 수 있었지만 번호 생성과 승인 처리가 클라이언트에 분산되어 있었다. 음수·초과 집행, 본인 승인, 승인 후 원장 수정, 결재함과 모듈 화면의 승인 결과 불일치가 가능했고 문서번호와 주차장 형태 연계도 불완전했다. 모바일에서는 1,100px 이상의 표를 가로로 이동해야 했다.

이번 단계는 새 기능 수보다 `편성 → 제출 → 분리 결재 → 집행/전용 신청 → 분석` 원장의 일관성을 우선했다.

## 실제 업무 흐름

1. 편성안 `2027년 주차빌딩 현장 안전설비 본예산 검증`을 문서번호 `제주시청-차량관리과-2026-0803-BP01`로 생성했다.
2. `[검증] 제주시청 현장연계 주차빌딩 (수정 확인)`에 `승강기·비상조명 안전보강` 38,500,000원을 편성하고 제출했다.
3. 제출자와 현재 사용자가 같을 때 승인 버튼 대신 다른 결재자 필요 안내가 표시되는 것을 확인했다.
4. 시설유지비에서 1,450,000원 집행을 문서번호 `제주시청-차량관리과-2026-0803-BE01`로 신청했다.
5. 시설유지비에서 인건비로 250,000원 전용을 문서번호 `제주시청-차량관리과-2026-0803-BT01`로 신청했다.
6. 집행과 전용 모두 현재 신청자에게 승인·반려 동작이 노출되지 않았고 서버 RPC도 SQLSTATE `42501`로 본인 승인을 거부했다.

## 핵심 개선

- 서버 시퀀스 기반 편성·집행·전용 번호 발급과 모바일 재시도용 `client_mutation_id`를 적용했다.
- 편성안 생성, 상태 전환, 집행 신청·결정, 전용 신청·결정을 원자적 RPC로 통합했다.
- 승인 후 상태·금액·항목 직접 수정과 모든 예산 원장 하드 삭제를 차단했다.
- 양수 금액, 잔액, 세입·세출 구분, 승인 예산안, 동일 회계연도, 전용 분류 규칙을 서버에서 재검증한다.
- 편성·집행·전용에 근거 문서번호를 필수화하고 문서대장 연결 대상을 추가했다.
- 예산항목과 집행에 주차장 및 `노외·주차빌딩·노상` 형태 스냅샷을 저장한다.
- 검색, 연도·상태·유형·주차장 형태 필터, 금액·날짜·번호·주차장 정렬을 추가했다.
- 모바일에서는 표 대신 카드로 전환하고 신청 금액, 문서번호, 주차장, 상태를 첫 화면에 표시한다.
- 결재함과 예산 모듈이 동일 승인 RPC를 호출하도록 통합했다.
- 분석은 선택 연도의 승인·집행완료 예산과 실제 집행완료 세출만 사용한다.

## 잔여 위험과 다음 단계

- 기존 이관 자료 중 문서번호가 없던 편성안은 `이관-예산-*` 번호로 보정했지만 집행·전용의 과거 증빙 문서번호는 원문 대조 후 보강해야 한다.
- 정식 운영에서는 예산 승인권자를 별도 계정으로 구성하고 역할별 RLS 회귀 검증이 필요하다.
- 집행 완료 건의 정정·취소는 원본 보존형 반대 전표 RPC로 추가하는 것이 다음 우선순위다.
- 예산과 입찰·계약·용역 대가지급의 금액 예약·확정 연결은 다음 입찰관리 및 용역관리 단계에서 이어서 검증한다.

## 측정 기준

- 잘못된 잔액: 0건
- 결재 경로별 결과 차이: 0건

- 본인 승인 및 승인 후 원장 직접 수정: 0건
