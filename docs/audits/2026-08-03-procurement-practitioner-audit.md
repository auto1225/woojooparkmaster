- 관찰 시각: 2026-08-03 20:10 KST
- 환경: 로컬 Vite 앱 + 연결된 Supabase 프로젝트
- 데이터 성격: 기능 검증용 샘플 데이터
- 주 사용자: 제주시청 차량관리과 운영팀 주무관, 예산·계약 담당자, 결재자

## 요약 진단

기존 입찰관리는 화면에서 사업을 만들 수 있었지만 번호 생성, 승인 분리, 예산 생애주기, 문서 원문, 계약 이관이 서로 느슨했다. 실제 입력 검증에서 `BD-2026-2027`과 같은 잘못된 번호, 실행 중 예산의 선택 불가, 수행기간 표시 누락, 문서 직접 쓰기, 모바일 가로 넘침 위험을 확인했다.

이번 개선으로 문서번호·승인 예산·주차장·입찰·계약·원문 증빙을 서버 명령과 감사이력으로 연결했다. 신규 검증 사업 `JJC-BID-2026-3001`과 원문 PDF를 실제 등록했고, 자기승인은 차단됐다.

## 업무 흐름

1. 예산 담당자가 승인 또는 집행 중인 지출 예산항목을 준비한다.
2. 입찰 담당자가 주차장, 근거 문서번호, 예산항목, 금액, 일정으로 입찰사업을 등록한다.
3. 담당자가 검토를 요청한다.
4. 별도 결재자가 결재함에서 공고 또는 반려한다.
5. 공고 후 참여업체, 평가, 낙찰, 계약을 단계별로 기록한다.
6. 용역·위탁 계약은 용역사업으로 인계하고, 공사·물품은 시설·장비 업무의 근거로 사용한다.
7. 공고문, 설계서, 과업지시서, 계약서, 보증서는 문서번호와 원문으로 보존한다.

## 지표 계약

- 이벤트: 입찰 초안 등록부터 검토 요청까지 완료
- 대상: 신규 입찰사업
- 계산: 완료 건의 중앙 처리시간, 입력 화면 수, 문서 미연계율, 승인 우회 실패율
- 기준선: 기존 화면 4개 이상 정보 묶음과 문서 별도 입력, 실제 운영 기준선은 미수집
- 목표: 2단계 등록, 필수 문서번호·예산·주차장 연계 100%, 자기승인 0건, 모바일 가로 넘침 0건
- 소유자: 차량관리과 입찰 담당자와 시스템 관리자

## 남은 제약과 다음 검증

- 현재 로그인된 계정 한 개로는 분리 승인 정책상 공고 완료까지 진행할 수 없다. 다른 결재자 계정으로 승인 후 업체접수·평가·계약·용역 인계를 이어서 검증해야 한다.
- 과거 데모 계약 일부는 주차장과 원문이 없다. 운영 전 이관 점검 목록으로 보완해야 한다.
- HWP 원문은 업로드·다운로드할 수 있으나 브라우저 미리보기는 제공하지 않는다.
- 실운영 성능 기준선은 샘플 데이터로 확정하지 않고 운영 로그로 수집해야 한다.
