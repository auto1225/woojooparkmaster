- 대상: 용역 등록, 사업 목록·상세, 마일스톤, 성과물, 검수, 지급, 이슈, 문서·예산·주차장 연계

## 사용 단계 검증

1. 신규 등록을 사업·업체와 감독·계약의 2단계로 완료했다.
2. 서버가 사업번호를 발급하고 사업과 3개 마일스톤을 한 트랜잭션으로 저장했다.
3. 목록에서 문서번호, 주차장 형태, 업체 담당자, 계약액, 기한, 진척·지급률을 확인했다.
4. 착수 처리 후 첫 마일스톤을 완료하자 진척률이 0%에서 10%로 갱신됐다.
5. 현장 이슈를 등록하고 처리 시작 후 해결 내용과 확인 결과를 기록했다.
6. 검수를 생성했으나 작성자 자기 승인 시도가 서버에서 거부됐다.
7. 미완료 마일스톤이 있는 상태에서 준공검수 요청이 서버에서 거부됐다.
8. 성과물 PDF를 제출하고 다운로드 링크가 실제 파일을 여는지 확인했다.
9. 성과물 제출자 자기 승인 시도가 서버에서 거부됐다.
10. 같은 예산에 잔액을 넘는 추가 계약과 승인 상태 검수의 직접 삽입이 모두 거부됐다.

## 구현된 개선

- 문서번호·예산·주차장 유형·업체 연락망·감독/검수 담당자 필수 연결
- 서버 발번, 모바일 재전송용 mutation ID, 행 버전, 감사 이력, 하드 삭제 차단
- 예산 약정 원장과 동시성 잠금으로 용역 간 예산 중복 점유 차단
- 상태 머신과 준공 선행조건 강제
- 사업 상태, 마일스톤, 이슈, 연락망을 서버 명령으로 처리
- 검사 작성자·승인자, 지급 요청자·승인자·지급 처리자 분리
- 지급 완료와 예산집행 원장 생성의 트랜잭션 연결
- 성과물 문서번호·원문 제출, 다운로드, 승인·보완 및 자기 승인 차단
- 노외·주차빌딩·노상 형태 필터와 문서·업체·담당자 통합 검색
- 모바일 목록·성과물 카드와 가로 스크롤 없는 등록 2단계 구조

## 우선순위별 남은 개선

### P1

- 용역 검수·지급 승인 단계를 공통 결재함의 `approval_records/steps`와 연결한다.
- 성과물 보완 재제출 시 이전 파일을 보존하는 버전 전용 테이블과 파일 SHA-256 검증을 추가한다.
- 지급 계좌번호는 재무 권한이 있는 사용자만 볼 수 있도록 별도 보안 뷰로 분리한다.
- 입찰계약에서 용역으로 인계하는 기존 RPC를 최신 입찰 쓰기 가드와 예산 약정 원장에 맞게 재작성한다.

### P2

- 검수·지급·이슈 독립 목록에 문서번호, 주차장 형태, 담당자, 기한, 금액 다중 정렬을 동일하게 적용한다.
- 실제 현장 모바일 앱에서는 사진 촬영, 위치, 오프라인 큐, 동기화 충돌 해결을 추가한다.
- 현재 인앱 브라우저의 뷰포트 오버라이드가 1280px로 고정돼 변경 후 390px 픽셀 측정은 자동 회귀 환경에서 재검증한다.
