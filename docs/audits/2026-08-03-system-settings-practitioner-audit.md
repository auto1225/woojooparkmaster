## 발견한 문제와 보완

1. 로그인 잠금 상태가 브라우저 RLS에 의존해 실제로 동작하지 않았다.
   - 이메일 존재 여부를 노출하지 않는 서버 잠금 조회 함수로 변경했다.
   - 익명 실패 누적 함수는 타인 계정 잠금 공격이 가능하므로 제거하고 Supabase Auth의 서버 제한에 맡겼다.

2. 관리자 세션 종료가 화면의 세션 행만 비활성화하고 실제 앱 로그아웃으로 이어지지 않았다.
   - 앱이 30초마다 현재 세션을 확인하고, Realtime 변경도 구독해 비활성 또는 만료 시 로그아웃한다.
   - 배포 시 기존 활성 세션에 30분 유예를 부여해 일괄 로그아웃을 방지했다.

3. 설정 복원이 여러 쿼리로 나뉘어 중간 실패 시 일부 값만 복구될 수 있었다.
   - 관리자 전용 `restore_system_config` 서버 함수에서 한 트랜잭션으로 복원하고 변경 이력도 함께 남긴다.

4. 일반 사용자가 활동 로그의 사용자명과 내용을 임의로 작성할 수 있었다.
   - 일반 업무 기록은 서버가 로그인 사용자를 확정하는 `write_activity_event`로 저장한다.
   - 직접 입력·삭제는 샘플 데이터 관리가 필요한 관리자만 허용한다.

5. 메시지 관리가 실제 문자 전송처럼 보였지만 외부 발송 공급자가 연결되지 않았다.
   - `발송 요청 등록`으로 용어를 수정하고, 공급자 연결 전에는 대기 상태임을 명시했다.
   - 전화번호 형식과 조회 실패 상태를 검증한다.

6. 보안 화면과 보고서가 온프레미스, TLS, 방화벽, 암호화를 검증한 것처럼 고정 표시했다.
   - 실제 조회 가능한 항목만 점수에 반영하고 나머지는 `확인 필요` 또는 `권장`으로 표시한다.
   - 조회 오류가 있으면 보고서를 공식 증빙으로 출력하지 못하게 한다.

7. 비밀번호 조합, IP 허용목록, 2단계 인증 설정이 실제 인증 흐름과 연결되지 않았다.
   - 비밀번호 조합은 `현재 앱 고정 정책`, IP·2단계 인증·로그인 시도 제한은 `인증 서버 연계 필요`로 읽기 전용 처리했다.

8. 결재선은 기본 결재선이 중복될 수 있고 편집 기능이 부족했다.
   - 문서 유형별 기본 결재선을 하나로 제한하고 생성·수정·삭제·기본 지정 오류 처리를 보강했다.

## 모바일·현장 관점

- 설정 탭과 표는 작은 화면에서 가로 스크롤되며 본문을 밀어내지 않는다.
- 메시지·결재선 표는 모바일에서 최소 폭을 유지해 열 제목과 값이 겹치지 않는다.
- 보안 자체점검 보고서는 설정 화면에서 한 번에 진입할 수 있다.
- 서버 정책이 필요한 설정은 현장 앱에서 임의로 토글할 수 없게 구분했다.

## 잔여 운영 준비

- 실제 문자·알림 발송은 공공기관 승인 공급자와 발신번호 등록 후 서버 발송 함수를 연결해야 한다.
- IP 허용목록과 2단계 인증은 Supabase Auth 앞단의 기관 인증 프록시 또는 SSO에서 적용해야 한다.
- 패키지 취약점은 화면에서 안전으로 고정하지 않고 CI의 `npm audit` 및 공급망 검사를 운영 증빙으로 관리해야 한다.
- 2026-08-03 `npm audit --omit=dev`의 고위험 2건은 React Router RSC 서버 액션 경로 대상이며 현재 `BrowserRouter` 정적 SPA에는 해당 경로가 없다. 향후 RSC 또는 서버 액션을 도입하기 전에는 반드시 보안 수정 버전으로 재검증한다.
