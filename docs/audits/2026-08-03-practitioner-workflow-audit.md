# 실무자 관점 전체 업무 연계 감사

- 기준 시각: 2026-08-03 KST
- 기준 커밋: `cd45228`
- 대상 부서: 제주시청 차량관리과 운영팀·시설 담당
- 방법: 시설, 민원, 운영·문서·보고서, UX·모바일, 데이터·권한의 5개 에이전트 정적 감사와 관리자 실사용 시나리오 결합

## 실제 수행 시나리오

1. 장비 등록, 업체 담당자 연결, 주차장·형태·종류 필터, 공식 문서 등록 및 문서번호 전체 검색
2. 시설 민원 접수, 처리기한·현장 위치 입력, 담당자 배정, 시설작업 자동 생성, 민원↔시설작업 왕복 이동
3. 96개 메뉴 접근 스모크, 브라우저 오류·경고 수집, 설정·보고서·문서 흐름 확인

검증 데이터는 제목에 `[검증]`을 붙여 운영 데이터와 구분했다. 민원인 연락처 등 개인정보는 보고서에 기록하지 않았다.

## 확인된 강점

- 민원에서 시설작업이 자동 생성되고 양쪽 상세 화면에서 원 업무로 왕복 이동할 수 있다.
- 장비와 민원 모두 주차장 형태(노외·주차빌딩·노상)를 표시하며 장비는 주차장, 형태, 종류, 상태, 날짜, 비용 다중 정렬을 지원한다.
- 장비·시설작업·민원에서 공식 문서를 연결하고 문서번호로 전체 검색할 수 있다.
- 유지보수 완료는 조치내용과 사진을 요구하고, 민원 현장업무는 모바일 카드형 화면을 제공한다.

## 우선순위 발견사항

### P0 보안

- 익명 세션에서 직원 프로필, 시스템 설정, 공통코드에 저장된 문서·업체·팀 업무 메타데이터가 조회됐다.
- 사용자가 자신의 프로필 행을 직접 수정해 역할·팀·활성상태를 바꿀 수 있는 정책이었다.
- 민원 월별 통계와 직원 성과 뷰가 호출자 RLS 없이 재생성돼 익명 조회가 가능했다.

조치: 익명 권한 회수, 인증 전용 조회 정책, 프로필 권한 필드 변경 방지 트리거, 통계 뷰 `security_invoker` 적용.

### P1 실무 연계·정확성

- 민원 담당자를 배정해도 이미 자동 생성된 시설작업은 미배정으로 남았다.
- 장비 250건이 한 화면에 모두 렌더링돼 조회와 스크롤 부담이 컸다.
- 결재선과 결재 단계 변경 정책이 모든 인증 사용자에게 열려 있었다.
- 화면의 자체 다중 정렬과 공통 테이블 DOM 정렬이 동시에 작동해 표시 순서가 달라질 수 있었다.
- 사진 업로드 실패와 상태 변경이 원자적이지 않아 현장증빙 없는 완료 또는 고아 파일 가능성이 있다.

조치: 민원→시설 배정 동기화 및 기존 데이터 보정, 장비 50건 페이지 처리, 자체 정렬 화면의 중복 DOM 정렬 해제, 결재 RLS 축소.

### P2 사용성·모바일

- 문서 필터 결과가 0건이면 안내 없이 빈 표처럼 보였다.
- 다수 표 행은 마우스 클릭만 지원해 키보드로 상세를 열기 어렵다.
- 민원 접수와 주차장 등록 같은 긴 양식은 임시저장·이탈 경고가 부족하다.
- 민원·시설 사진은 조사 모듈의 IndexedDB 오프라인 큐를 재사용하지 않아 통신 불량 시 재촬영 위험이 있다.
- 목록 필터가 URL에 충분히 보존되지 않아 상세에서 돌아왔을 때 업무 맥락이 사라지는 메뉴가 많다.

조치: 문서 0건 상태와 초기화 동작, 문서·장비 식별자 키보드 버튼, 장비 페이지·필터 URL 보존을 우선 적용. 오프라인 명령 큐와 공통 이탈 방지는 다음 수직 기능 단위로 추진한다.

## 후속 로드맵

1. 현장 사진과 명령을 함께 보관하는 IndexedDB 오프라인 큐를 민원·시설 완료에 공통 적용한다.
2. 회신·종결·현장방문·시설완료를 첨부 증빙과 함께 원자적으로 처리하는 RPC로 통합한다.
3. 문서·팀 업무를 `code_master` 임시 원장에서 전용 FK 테이블로 이관한다.
4. 모든 목록에 공통 오류/재시도/진짜 빈 상태와 URL 기반 필터 복원을 적용한다.
5. viewer, editor, manager 역할별 메뉴·버튼·RLS 계약 E2E를 CI에 추가한다.
