- 기획 에이전트: 공공기관 문서 추적성, 보안등급, 감사이력, 모바일 현장 연계를 기준으로 누락 기능 분석
- 연계 기준: 노외주차장, 주차빌딩, 노상주차장 유형을 문서 검색과 업무 문맥에 유지

- 담당부서: 제주시청 차량관리과 운영팀

## 모바일 앱 연계 기준

- 모바일은 문서번호·업무 ID를 서버 ID와 함께 보관해야 하며 표시 문자열만 복사하지 않는다.
- 현장 사진·원문 업로드에는 `client_mutation_id`, 재시도 큐, 업로드 상태와 실패 복구가 필요하다.
- 주차장 형태는 문서에 복사해 고정하지 않고 연결된 주차장 원장에서 조회한다.
- 모바일 상세에서 문서 원문 열기, 민원·장비·주차장 이동, 관계 확인이 한 화면 안에서 가능해야 한다.
- 오프라인 작성은 초안까지만 허용하고 발송·접수·보존 전에는 서버 원문 존재를 재검증해야 한다.

## 잔여 구조 위험

1. 실행 데이터가 전용 `official_documents`·`document_links` 대신 `code_master`·`attachments`를 사용한다. 전용 원장으로 이관하려면 데이터 검증, FK, RPC, 롤백 계획이 포함된 별도 배포가 필요하다.
2. 문서 메타데이터 저장과 스토리지 업로드는 단일 트랜잭션이 아니다. 업로드 실패 시 문서는 등록되고 파일만 실패할 수 있으므로 재시도 상태 모델이 필요하다.
3. 현재 목록은 전체 자료를 내려받아 클라이언트에서 필터링한다. 운영 데이터가 커지면 서버 검색, 커서 페이지네이션, 인덱스 기반 정렬로 전환해야 한다.
4. 감사로그는 클라이언트 기록에 의존한다. 최종 운영 단계에서는 DB 트리거나 서버 RPC에서 사용자·전후값을 기록해야 한다.
5. 비공개 문서는 관리자 또는 동일 부서 기준으로 제한했다. 실제 기록물 보안 규정에 따라 개인 지정, 열람그룹, 대외주의 다운로드 워터마크가 추가될 수 있다.
