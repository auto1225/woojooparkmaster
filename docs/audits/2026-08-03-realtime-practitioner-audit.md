# 실시간 정보 실무자 검수 보고서

## 검수 범위

- 실시간 현황, 센서, 게이트웨이, 안내전광판, 외부 API
- 제주시청 차량관리과 운영팀의 관제·현장조치 흐름
- 노외주차장, 주차빌딩, 노상주차장 구분
- 모바일 재전송, 중복 등록, 장치 수명주기, 보안 키 취급

## 발견 사항과 조치

| 구분 | 발견 사항 | 조치 |
| --- | --- | --- |
| 실시간 현황 | 112시간 전 값이 현재 잔여면처럼 표시됨 | 30분 초과 자료를 통계에서 제외하고 `데이터 지연`으로 표시 |
| 센서 상태 | 저장 상태 `active`와 통신 두절이 정상/오프라인 양쪽에 중복 집계됨 | 마지막 통신, 오류, 배터리를 합친 단일 건강상태 규칙 적용 |
| 전광판 | DB 갱신만으로 전송 성공 처리 | 전송 요청 대기열과 장비 응답 확인을 분리하고 응답 전에는 `응답 대기` 표시 |
| 전광판 안전 | 오래된 잔여면을 그대로 전송 | 자료 지연 시 `데이터 점검 중` 표출 요청 |
| 장치 등록 | 모바일 재전송 시 중복 등록 가능 | `client_mutation_id` 기반 멱등 등록 명령 적용 |
| 주차장 유형 | 노상 장치에도 층 정보가 저장될 수 있음 | 노상주차장 등록 시 서버에서 층 값을 제거하고 유형 스냅샷 저장 |
| 센서 수집 | 임의 장치·중복 이벤트·미래 시각 자료 저장 가능 | 등록 장치/주차장 검증, 이벤트 ID 중복 차단, 미래 시각 차단 |
| 점유 집계 | 반복된 동일 점유 신호가 입출차를 중복 증가시킴 | 직전 상태 전환만 입·출차로 집계하고 주차장 기준 총면수 사용 |
| API 키 | 키 원문을 목록에서 재조회할 수 있고 브라우저에서 생성 | 서버 난수 생성·해시 저장·1회 노출·폐기 명령 적용 |
| 외부 API | 화면에 엔드포인트만 있고 실제 처리 함수가 없음 | Edge API 배포, 키 검증·만료·호출제한·호출로그 연결 |
| 장치 관리 | 등록 후 수정·보관 절차 없음 | 버전 충돌 검증 수정 명령과 의존관계 기반 보관 차단 추가 |
| 모바일 | 네트워크 재시도와 동시 수정 충돌을 식별할 수 없음 | 멱등 ID와 `row_version`을 장치 등록·수정에 적용 |

## 실제 실행 증거

- 노상주차장 `PM-REAL-003 용담해안도로 공영주차장`에 게이트웨이 `GW-AUDIT-ONSTREET-0803` 등록
- 같은 주차장과 게이트웨이에 센서 `SEN-AUDIT-ONSTREET-0803` 등록
- 센서 등록 시 입력한 층 `4`가 노상주차장 규칙에 따라 저장 결과에서 제거됨
- 센서명과 관리 상태를 수정하고 목록의 `점검중` 반영 확인
- 안내전광판 `DSP-AUDIT-ONSTREET-0803` 등록 후 전송 요청 실행
- 오래된 자료 때문에 표출 문구가 `데이터 점검 중`, 상태가 `응답 대기`로 기록됨
- 연결 센서가 있는 게이트웨이 보관 거절 확인
- 전송 대기 명령이 있는 전광판 보관 거절 확인
- API 목록 113개소 조회, 모두 오래된 자료로 판정되어 점유 수치가 비공개 처리됨
- `PM-REAL-003` 개별 조회와 기간별 이력 조회 실행
- 폐기한 API 키 재호출 시 HTTP 401 확인
- 검증용 API 키는 실행 후 모두 폐기함

## 후속 운영 조건

- 장비 어댑터는 `display_push_commands`의 대기 명령을 전송한 뒤 서비스 역할로 수신 성공/실패를 회신해야 한다.
- 센서 수집기는 사용자 세션이 아니라 서비스 역할로 이벤트 ID를 포함해 자료를 저장해야 한다.
- 모바일 앱은 등록 명령마다 동일 요청 ID를 재사용하고 수정 전에 최신 `row_version`을 받아야 한다.
