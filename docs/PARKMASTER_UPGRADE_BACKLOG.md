# ParkMaster 업그레이드 백로그

이 문서는 개발 순서와 인수 기준을 관리한다. 우선순위는 실제 사용 로그와 사용자 인터뷰 결과로 갱신한다.

## P0. 즉시 처리

| ID | 작업 | 사용자 가치 | 완료 조건 |
|---|---|---|---|
| PM-001 | 네이버 지도 실패 격리 | 지도 설정 문제에도 홈과 비지도 업무 사용 가능 | SDK, 타일, 마커 실패가 지도 영역 오류 상태로 제한되고 홈은 유지됨 |
| PM-002 | 결재 조회 스키마 오류 수정 | 제출된 업무가 빈 결재함으로 사라지지 않음 | 실제 DB 타입과 모든 결재 조회 필드 일치, 오류 로깅 및 테스트 추가 |
| PM-003 | 조사 승인 원자 명령 | 조사, 주차장, 알림, 감사기록의 불일치 방지 | 권한, 상태전이, 중복방지, 전체 롤백 DB 테스트 통과 |
| PM-004 | 라우트/행동/DB 권한 정렬 | 역할과 라이선스에 맞는 기능만 사용 | 역할별 URL, 버튼, RPC, RLS 테스트 통과 |
| PM-005 | 핵심 상태전이 서버 강제 | 잘못된 순서의 상태 변경 방지 | 조사부터 전이 규칙 적용, 미정의 엔터티 fail-closed |
| PM-006 | 첫 E2E 업무 테스트 | 실제 업무 흐름의 회귀 방지 | 조사 제출, 결재함 노출, 승인/반려, 권한 실패 자동화 |
| PM-007 | 민원 기한 초과 계산 정합성 | 실제 초과 건을 놓치지 않음 | 목록, KPI, 통계가 같은 기준일/시간대와 `due_date`로 계산 |
| PM-008 | 민원 개인정보 조회 범위 제한 | 불필요한 개인정보 노출 방지 | 역할/팀/담당 범위의 RLS와 직접 쿼리 테스트 통과 |
| PM-009 | 민원 인수/배정 원자 명령 | 담당 확정과 알림/이력을 안전하게 처리 | 동시성, 전체 롤백, 중복 알림 방지 DB 테스트 통과 |
| PM-010 | 안전한 민원 분류 E2E | 접수에서 담당 확정까지 실제 흐름 보장 | 필터, 인수/배정, 권한 실패, 모바일 핵심 정보 자동화 |

## P1. 매일 쓰는 기능

| ID | 작업 | 사용자 가치 | 완료 조건 |
|---|---|---|---|
| PM-101 | 역할별 `내 업무` 홈 | 로그인 즉시 오늘 처리할 업무 확인 | 긴급, 초과, 오늘 마감, 미배정, 결재 대기 필터와 딥링크 |
| PM-102 | 공통 업무 읽기 모델 | 모듈마다 따로 찾지 않고 한 큐에서 확인 | 민원, 유지보수, 점검, 조사, 결재를 사용자/팀 기준 조회 |
| PM-103 | 유지보수 실제 담당자 배정 | 누가 언제 처리할지 명확 | 배정자, 담당자, 알림, 착수시간, 변경이력 저장 |
| PM-104 | 예방정비 작업지시 생성 | 예정 점검이 실제 작업으로 이어짐 | 도래 일정에서 중복 없는 작업 생성 및 다음 주기 갱신 |
| PM-105 | 유지보수 증빙과 검증 | 완료 품질과 비용 추적 | 전후 사진, 작업시간, 부품, 비용, 독립 검증자 기록 |
| PM-106 | 민원 SLA 예약 감시 | 갱신되지 않은 민원도 기한 초과 감지 | 정기 재계산, 사전 경고, 초과 에스컬레이션, 환경설정 반영 |
| PM-107 | Parking Lot 360 진행업무 | 주차장 단위로 열린 업무와 비용 파악 | 열린 민원/정비/점검/사업/결재 타임라인과 빠른 행동 |
| PM-108 | 현장 조사 오프라인 완결 | 통신 불안정에서도 데이터 손실 없이 조사 | 단계별 큐, 사진 재전송, 충돌 표시, 재시도/취소, 동기화 상태 |
| PM-109 | 모바일 `더보기`와 작업 행동 | 현장에서 전체 핵심 기능 접근 | 실제 메뉴 시트, 역할별 항목, 터치 접근성, 작은 화면 검증 |

## P2. 재정/계약

| ID | 작업 | 사용자 가치 | 완료 조건 |
|---|---|---|---|
| PM-201 | 일별 수입 누락 탐지 | 빠진 주차장/일자를 마감 전에 발견 | 대상 주차장 x 날짜 완전성 검사와 예외 사유 |
| PM-202 | 정산 파일 가져오기 | 반복 입력과 오타 감소 | 템플릿, 검증, 오류행 다운로드, 중복 방지, 감사 이력 |
| PM-203 | 월 마감 잠금 | 마감 후 임의 변경 방지 | maker-checker, 차이 사유/증빙, 재개방 권한과 이력 |
| PM-204 | 입찰에서 용역 인계 | 계약 정보를 다시 입력하지 않음 | 낙찰 계약으로 용역사업 생성, 출처 링크와 필드 매핑 |
| PM-205 | 검사/보완/재검사 흐름 | 대금 지급 전 품질 조건 확인 | 성과물, 검사, 보완기한, 재검사, 결과 증빙 연결 |
| PM-206 | 지급 요청과 결재 | 검사 완료 건만 정확히 지급 | 계약/기성/검사/예산 검증과 결재 명령 연결 |
| PM-207 | 실제 보고서 생성/예약 | 행정 보고 작업시간 감소 | PDF/Excel 파일, 원천 합계 검증, 예약 실행과 전달 상태 |

## 다음 스프린트 제안

기간: 2주

1. `PM-001` 네이버 지도 실패 격리
2. `PM-002` 결재 조회 스키마 수정
3. `PM-007` 민원 기한 초과 계산 정합성
4. `PM-008` 민원 개인정보 조회 범위 제한
5. `PM-009` 민원 인수/배정 원자 명령
6. `PM-010` 접수부터 담당 확정까지 E2E 테스트

다음 스프린트에서는 `PM-003`, `PM-004`, `PM-005`, `PM-006`으로 조사 승인과 결재 무결성 표준을 완성한다.

스프린트 종료 시 다음 증거를 확보한다.

- 홈 접근 성공률
- 결재 큐 오류 건수
- 정확한 민원 기한 초과 건수와 미배정률
- 접수부터 담당 확정까지의 처리시간
- 인수/배정 중복 및 부분 반영 테스트 결과
- 역할별 허용/거부 매트릭스
